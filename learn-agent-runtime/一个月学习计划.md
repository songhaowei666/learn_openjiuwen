# openJiuwen Agent Runtime — 一个月学习计划

> 适用对象：需要基于本仓库做**高码开发 / 二次开发**，并支撑**多项目组 Agent 托管与管理**的同学。  
> 学习节奏：约 4 周，每周 5 个工作日；每日建议投入 **1.5～3 小时**（可按实际情况压缩/拉长）。  
> 原则：**先跑通 → 再读核心路径 → 再动手改 → 最后形成可落地的二次开发方案**。

---

## 学习目标（一个月后应达到）

1. 能独立启动 Runtime，完成一次低码或高码 Agent 部署与调用。
2. 说清架构分层：`server` / `management` / `service` / `foundation` / `applications` / `cli` 各自职责。
3. 能自己写一个 `AgentApp`，并用 CLI 打成 WHL 部署。
4. 理解多租户（`user_id` / `space_id`）的能力边界与缺口。
5. 能列出一份「多项目组二次开发」改造清单（改哪些模块、不改哪些）。

---

## 总览（四周主题）


| 周次    | 主题          | 产出物                     |
| ----- | ----------- | ----------------------- |
| 第 1 周 | 定位与跑通       | 本地可访问的 Runtime + 一次成功调用 |

| 第 3 周 | 高码 Agent 实战 | 自研 Agent 工程 + CLI 部署成功  |
| 第 4 周 | 二次开发与治理设计   | 多项目组方案文档 + 小改动 PoC      |

## 每日学习方法（建议）

1. **先问题后代码**：每天带着 1 个问题读（例如「删除会不会清 venv？」）。
2. **路径跟踪优于广撒网**：沿 `main.py → manager → strategy → deployer` 跟一次比到处翻强。
3. **笔记只留三样**：时序图、关键类表、能力缺口表。
4. **改代码前先标边界**：能配置解决的不改；能中间件解决的不改 Manager；尽量不动 `foundation`。

## 风险与避坑


| 坑                   | 说明                           |
| ------------------- | ---------------------------- |
| 只跑 `AgentApp.run()` | 体会不到 Runtime，要走到 deploy      |
| 把本仓当 WorkSwarm      | 两边是共享 foundation 的不同产品       |
| 一上来上 AgentOS        | 对二次开发过重，先改 Runtime           |
| 以为有 workspace       | 目前只有部署目录，业务工作区需自建            |
| 以为多租户已完备            | 仅有标签与列表过滤，鉴权需自补              |
| 高码走 HTTP deploy     | 当前管理面 deploy 偏 IR 低码；高码先 CLI |
