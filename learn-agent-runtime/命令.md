### 管理面全部业务接口（:8186）

| 方法 | 路径 |
|---|---|
| `GET` | `/health` |
| `POST` | `/api/v1/agents/deploy`（仅低码 IR） |
| `GET` | `/api/v1/agents` |
| `GET` | `/api/v1/agents/{deployment_id}` |
| `DELETE` | `/api/v1/agents/{deployment_id}` |

框架自带：`/docs`、`/redoc`、`/openapi.json`。

```bash
curl -s http://127.0.0.1:8186/health
curl -s http://127.0.0.1:8186/api/v1/agents
curl -s http://127.0.0.1:8186/api/v1/agents/<deployment_id>
curl -s -X DELETE http://127.0.0.1:8186/api/v1/agents/<deployment_id>

# 低码部署示例（需 IR + MODE=dev 时还要 lowcode_agent_runner whl）
curl -s -X POST \
  "http://127.0.0.1:8186/api/v1/agents/deploy?name=demo&mode=subprocess" \
  -F "file=@/path/to/ir.json"
```

说明：高码发布走下面 CLI，不走 `POST .../deploy`。无 stop/start/restart HTTP。

## 高码 Agent（CLI）

```bash
# 首次依赖（一般已装过可跳过）
# uv pip install -e ./cli -e ./foundation -e ./management
# uv build foundation --out-dir dist
# uv build service --out-dir dist

# 创建（示例）
openjiuwen new agent day4-echo --template empty --output-dir ./learn-agent-runtime

# 部署 / 列表 / 删除
openjiuwen agent deploy ./learn-agent-runtime/day4-echo --port 8090
openjiuwen agent list
openjiuwen agent get <deployment_id>
openjiuwen agent delete <deployment_id>
```

样例工程：`learn-agent-runtime/day4-echo`  
改逻辑：`openjiuwen_runtime/day4_echo/day4_echo_runner.py` 的 `@app.query`

## 业务 Agent 对话（:8090，不经 server）

```bash
curl -s http://127.0.0.1:8090/health

curl -s -N -X POST http://127.0.0.1:8090/query \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"你好"}],"conversation_id":"c1"}'

curl -s -X POST http://127.0.0.1:8090/reset_conversation \
  -H 'Content-Type: application/json' \
  -d '{"conversation_id":"c1"}'
```

注意：字段名是 `messages`。

## 踩坑

- 在 `server/` 下跑 `openjiuwen agent list` → 读的是 `server/deployments.db`，可能是空的。
- server 从 `server/` 启动 → 同样看不到仓库根 CLI 部署的高码实例。
- 管理面控制偏弱：HTTP 只有 list/get/delete，无 stop/start/restart。
